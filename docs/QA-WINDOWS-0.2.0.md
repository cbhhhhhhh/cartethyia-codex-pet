## 安装与数据

使用已公开并校验的 Windows 0.1.0 EXE（SHA-256 `611ba7070bbed4f24313f4f008ca5ca68e3348f4b2978c4f8ff563a9d46c007a`）。空目录首次安装 0.2.0 成功。从另一个隔离的 0.1.0 档案执行 `0.1.0 → 0.2.0 → 0.1.0 → 0.2.0`，每次比对设置、人设、聊天、记忆和待办。卸载后，该实例的程序已移除，Codex 配置的其他字段及测试中后来添加的配置均保留。

随后从同一 EXE 升级当前用户的桌宠。核对常驻进程的完整安装路径、卸载项及插件注册，逐文件比较全部 272 个安装文件与构建目录。升级前备份个人数据，升级后比较档案和待办。开始菜单指向安装目录与卡提图标，托盘成功加载图标，三次再次启动均由原 PID 打开设置。

两个子会话共跳过 39 条继承记录。本轮父子实测出现 JSONL 和 SQLite 事件。另案使用真实已注册 hook、待审批和中断回合，并用定向夹具经同一 Windows 命名管道重放继承行、重写时间戳、迟到工具、重复终止、Stop、SubagentStop 和计划全勾。正常通知依次弹出，输入期间排队，同一线程开启下一回合后过时通知作废。无终态时，人工推进超时到期，恢复待机。

从 Codex 记录时间量到安装版 Qt 窗口实际的首次绘制。成功及失败含短暂反馈动作，待机延迟包含该动作。每个回合另开诊断窗口，仅跟随该合成任务。

真实 `account/rateLimits/read` 返回的 10,080 分钟窗口显示为「7 天额度」，已用、剩余、下次重置和更新时间均有值。`account/usage/read` 为合成回合提供 summary、dailyUsageBuckets、threadUsage 三个顶层字段，本账户此次未提供可归因的回合金额。在本地同形字段夹具中验证起止快照差值 0.3 积分、真实的原生美元 0 及缺失字段「暂未提供」。缓存输入和推理输出只作明细，合计直接使用来源的 total_tokens。当前任务用量可切换两个真实主回合。

## 解锁后可亲手复核

1. 把记事本放在卡提透明角落后方，用实体鼠标点一下，再点她的身体输入文字。慢拖到屏幕中间停住，接着画圈松手，观察屏幕边缘反弹。
2. 若接上第二台实体显示器，为两屏设不同缩放，把卡提放到副屏中间，退出后重开检查位置。本机多屏证据来自 Qt 双屏配置，实机只接一台 G52E。
3. 在 Codex 设置中审阅 pet-plus 的 hooks，新开一个本机任务。点击完成气泡中的「回到会话」，确认实际选中的聊天，播放一条回复确认个人扬声器。两个排队通知的跳转按钮均把对应线程的 URI 交给 Qt，Windows 已注册 codex: 处理程序。锁屏期间未目视确认所选页签。Windows 10 与其他实体配置未在本机运行。安装包未作 Authenticode 签名。
