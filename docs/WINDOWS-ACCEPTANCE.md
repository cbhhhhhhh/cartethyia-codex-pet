# 卡提希娅 Windows 本机验收

本报告记录 Windows 0.1.0 这条产品线首次发布时的真机验收。当时的版本号是 2.2.0，以下文件名、SHA-256 和一小时采样均对应当时的安装包。重编号后的安装包有独立的校验清单。[0.1.0 发布页](https://github.com/cbhhhhhhh/cartethyia-codex-pet/releases/tag/v0.1.0)

验收日期为 2026 年 11 月 25 日，机器使用北京时间。最终安装包为 **Cartethyia-2.2.0-Windows-x64-Setup.exe**，SHA-256 为 `d41c6ef07c4b7e475dc6bdf80121d8fcb83ae920a01ae194dc147728c32d3105`。验收结束时，主档案的桌宠留在登录用户会话 2 的桌面右下方。[测量原始摘要](windows-qa/results.json)

## 0.1.0 安装包复核

使用与原发行包 SHA-256 匹配的运行时和启动器，从本版源码重新封装了 Inno Setup 安装器。在 macOS 上的隔离 Wine 环境执行新 EXE 后，Windows 卸载注册表的 DisplayVersion 为 `0.1.0`，安装目录的 262 个随包文件与构建目录逐一校验一致。下文的 Windows 11 桌面和一小时数据属于原生 Windows 验收。

## 真实 Codex 回合

验收使用真实本机 app-server 和 Codex 会话记录。测试观察窗口加载已安装的程序代码，并按验收线程 ID 过滤其他同时运行的会话。下表从 Codex 记录的事件时间测到 Qt 对应状态的首次绘制。成功和失败会先播放短动作，再回到待机。审批使用真实只读命令请求，测试客户端等待两秒后拒绝。失败回合指定一个不可用的模型。

| 回合 | 开始到思考 | 终止到首帧 | 终止到待机 | 实际状态 |
| --- | ---: | ---: | ---: | --- |
| 正常执行 Get-Date | 52 ms | 54 ms | 612 ms | 思考、工作、检查、成功、待机 |
| 中断 | 82 ms | 38 ms | 38 ms | 思考、待机 |
| 失败 | 108 ms | 20 ms | 590 ms | 思考、失败、待机 |
| 遇到审批的回合 | 80 ms | 70 ms | 634 ms | 工作、等待审批、成功、待机 |

本轮真实 PermissionRequest 到等待审批首帧为 **184 ms**。拒绝命令后，这次回合未提供单独的 PostToolUse，审批状态随回合终止清除。测试进程核对并临时信任本项目七条 hook，日常 Codex 中的新 hook 仍需由用户审阅。安装版也能只读跟随 rollout 与当前客户端的分页历史。三项 stdio MCP 工具已实测完成状态读取、中文待办添加和完成。真实额度快照已在右键「查看额度」中显示。

## 桌面、聊天与隐私

- Windows 命中测试在桌宠透明角落找到了后方测试按钮。向命中的 HWND 投递按下和松开，按钮状态改变。角色身体命中桌宠 HWND。同时验证了分层、置顶属性。
- 向安装版真实窗口定向投递 Windows 鼠标消息。慢拖至屏幕中间并停顿后保持原位。画圈和左右摇动后的水平运动范围分别为 2380 和 2380 个物理像素，均测到侧墙反向运动。最后把角色留在右下。
- Qt 事件和 Windows UI Automation 覆盖了悬停工具、耗时、计划字段，右键菜单，头顶输入框、宽幅插画回复，设置重开和即时大小变动。快捷键改为 K 后验证旧键已释放、新键已注册，窗口响应 WM_HOTKEY 收起和唤醒。在 100%、125%、150%、200% 四种有效缩放下，每种检查了 9 个位置，包括带负坐标及上下错位的工作区。Qt 虚拟双屏上还实际将窗口从 100% 屏拖到左侧 150% 屏，再创建新窗口，恢复到副屏逻辑坐标（-924，302）。
- 真正从空模型目录点击文字模型下载按钮，208.27 秒后 CPU 引擎、Vulkan 引擎和文字权重全部通过固定 SHA-256 校验。Vulkan 枚举到 RTX 5060 Ti。强制 CPU 路径也完成了本机推理。
- 安装代码实际得到 27 次不同的增量文字更新。气泡中断测试在第 4 次更新后停止，聊天历史保持原值。视觉模型也回答了原角色插画的提问，图片保存在该测试档案内。主桌宠另行验证中断后推理进程退出，并通过界面清空了专门生成的一条验收记录。
- 两个独立档案分别保存人设与记忆，自定义角色从自己的图集取帧。五分钟间隔测试按真实墙钟运行，静音、专注和安静时段会抑制碎碎念，条件解除后收到提示。到期的 SQLite 待办也触发通知。
- Windows SAPI 中文语音 Microsoft Huihui Desktop 合成了 135,592 字节的 WAV。Windows 命名管道和配置备份目录的 DACL 都只授权当前用户。待机桌宠进程的网络连接检查为零。
- Python 回归共发现 28 项，25 项通过，3 项依赖 Darwin vnode 或 Mac Unix 数据报环境，按平台跳过。上述 Windows 窗口、管道、真实回合及安装测试单独运行。

## 一小时稳定性

从 **2026-11-25T14:04:47+08:00** 到 **2026-11-25T15:04:47+08:00**，同一安装版 GUI 进程 PID 43064 连续被观测 **3600.01 秒**，每 30 秒采样，共 **121 次**。期间测试过真实 Codex 活动、命名管道、聊天中断和桌面手势。异常退出 **0 次**。[逐次采样](windows-qa/soak-samples.jsonl)

| 桌宠 GUI 指标 | 实测 |
| --- | ---: |
| 累计 CPU 时间 | 0.375 秒 |
| 平均 CPU（一个逻辑核心满载为 100%） | 0.010% |

| 工作集采样中位数 | 96.81 MiB |
| 工作集采样峰值 | 96.98 MiB |

按需推理进程和 GPU 显存另计。在一次主桌宠聊天中断测试中，短时观察到模型进程工作集 456.38 MiB，随后确认进程退出。另用完整文字回复测量推理进程的 Windows 峰值工作集，CPU 路径为 1805.57 MiB，Vulkan 路径为 1975.16 MiB。30 秒采样可能错过短时峰值。验收期间物理控制台锁屏，解锁后的前台合成负载仍需另测。

## 需要本人在桌面确认

1. 解锁并从托盘唤醒卡提。把记事本放在她透明角落后面，用鼠标实际点一次。再改点身体，确认头顶输入框获得键盘焦点。按住身体慢拖至中间，停顿松手，再快速画圈后松手。
2. 如有第二台显示器，设置不同缩放后跨屏拖动，在副屏中间松开，重开桌宠核对原位。本机当前只枚举到 G52E 一台屏幕，前述多工作区检查使用模拟几何。
3. 打开 Codex 设置 → Hooks，审阅 pet-plus@cartethyia-windows-local 的七项。新建本机任务，点完成气泡的「回到会话」，核对选中的聊天。此机已注册 codex: 且系统接受测试 URI。锁屏期间未确认用户所见的最终页签。播放一条回复可确认个人默认音频设备。

本机用于核对计划的 CLI 回合没有提供 update_plan，只产生了文字清单。此时计划栏显示空值。可解析的结构化计划才显示完成数。额度显示收到的用量快照。macOS 二进制和其他 Windows 版本、未提升权限的独立标准账户及实体双屏不在本次实机样本内。
